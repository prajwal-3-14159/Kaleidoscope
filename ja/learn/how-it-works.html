5 つのフラクタルを 1 つの式で

エクスプローラーのどの脱出時間型フラクタルも、1 つのルールとして書き表せます。今の数 z を用意し、必要なら折りたたみ（「前処理」のステップ）をし、p 乗し、必要ならその結果を折りたたみ（「後処理」のステップ）、定数 c を足します。

z→post⁡(pre⁡(z)p)+c

テキスト表記：z → post(pre(z)^p) + c

折りたたみとは小さな反射のことで、実部の絶対値、虚部の絶対値、または複素共役をとる操作です。折りたたみ方が違えば、フラクタルも変わります。べき乗が 2 で、z=x+iy および c=a+ib と書くと、次のようになります。

フラクタル折りたたみ1 ステップ
マンデルブロなしx′=x2−y2+a、y′=2xy+b
バーニングシップ2 乗の前に |x|、|y|x′=x2−y2+a、y′=2|x||y|+b
トライコーン2 乗の前に共役x′=x2−y2+a、y′=−2xy+b
ケルト2 乗の後に |Re⁡|x′=|x2−y2|+a、y′=2xy+b
バッファロー2 乗の前に両方、後に |Re⁡| と −|Im⁡|x′=|x2−y2|+a、y′=−2|x||y|+b

マンデルブロ型の表示は z=c から始まり、ピクセルに応じて c を変えます。ジュリア型の表示は c を固定し、出発点の z を変えます。べき乗 p は 1.5 から 12 までの任意の値にできます。整数のときは正確な繰り返しの掛け算を使い、分数のときは複素べき乗の主枝を使うため、継ぎ目が残ります。

脱出時間の反復

エクスプローラーは、ピクセルごとにこのルールを繰り返し、z の大きさを見守ります。|z|2 が 65536 を超えたとき、つまり |z| が発散半径 R=256 を超えたとき、そのピクセルは脱出したと判定され、ループは止まります。反復回数の上限まで生き残ったピクセルは、黒く塗られます。上限は自動で決まり、ズームするほど大きくなります。深い表示では、近くの点どうしを区別するのにより多くのステップが必要になるからです。マンデルブロ集合の古典的な発散半径はわずか 2 ですが、これより大きくとると、次に説明する滑らかな色付けがうまく働きます。

滑らかな色付け

ステップ数を整数のまま数えると、見苦しい縞が出ます。これを直すのが小数の回数で、軌道が最後のステップのどのあたりまで進んで脱出したかを表します。z を、n ステップ後の最終的な値、R を発散半径とすると、次のようになります。

μ=n−logp⁡log⁡|z|2log⁡R2

テキスト表記：mu = n − log_p( log|z|² / log R² )

考え方は単純です。軌道が 0 から遠く離れているとき、もう 1 ステップ進むと大きさはおよそ p 乗になり、log⁡|z|2 はおよそ p 倍されます。この比の logp⁡ をとると、軌道が発散半径をステップのどのくらいの割合だけ飛び越えたかがわかります。実際のべき乗 p を使うことで、固定の log⁡2 を使うよりも、どのべき乗でも帯が連続になります。

この数 μ は、次にパレット上の位置に対応づけられます。既定のクラシックは、外側の帯から反復回数の上限まで、パレットを 1 回だけなぞります。そのため、上限を変えると色がずれます。平方根、対数、線形の 3 つの循環マッピングは、μ だけで決まります。違いは、集合の近くにある大きな値をどれだけ圧縮するかで、そのために帯が幅広く見えたり、細く見えたりします。パレットは OKLab 色空間で混ぜ合わせています。同じ大きさの変化が、目には同じ程度の違いに見えるように設計された色空間です。密度とオフセットのスライダーはパレットを伸縮・移動させ、C キーはそのオフセットをアニメーションさせます。これがカラーサイクルです。

距離推定とレリーフ照明

各ステップでは、2 × 2 のヤコビ行列も一緒に更新していきます。これは、出発点のわずかな変化がどれだけ強く拡大されるかを記録する、小さな数の表です。ヤコビ行列の大きさ |J| から、エクスプローラーは距離推定、つまり各ピクセルが集合からおよそどれだけ離れているかを求めます。

d≈|z|ln⁡|z||J|

テキスト表記：d ≈ |z| ln|z| / |J|

これはフィラメント・シェーディングでは、細く明るい糸として現れます。単純な脱出回数では見落としてしまう構造です。レリーフ・シェーディングでは、脱出ポテンシャル log⁡|z| のなめらかな輝きを、起伏のある地形とみなします。その傾きの方向（JTz に比例します）が面の法線になり、角度を調整できる光源からの通常の拡散反射と鏡面反射によって、縁が立体的に見えます。

プログレッシブ・アンチエイリアス

ドラッグやズームをしているあいだ、エクスプローラーは高速で粗いプレビューを描きます。表示が止まると、各ピクセルの内側のランダムにずらした位置でサンプルを追加し、その平均をとります。ピクセルあたり 1、4、8、16 個から、ディテールセクションで選べます。これがアンチエイリアスです。作業は小さな帯に分けて行われるので、ページは応答し続けます。

とても深くへ：摂動法

コンピューターは、たいていの数を、有効数字およそ 7 桁（32 ビット）か 16 桁（64 ビット）で保存します。拡大率 1030 では、隣り合うピクセルの違いがその桁数をはるかに超えた細かさになり、通常の計算はブロック状に崩れてしまいます。そこで使われるのが摂動法で、難しい計算を 1 回だけにするという工夫です。

エクスプローラーは、表示の中心でただ 1 本の参照軌道 Zn を、非常に高い精度で計算します。多倍長整数（BigInt）を使い、深く進むほど桁数を増やします。そのあと、各ピクセルはその軌道からの小さな差 δn だけを追いかけ、差がどう変化するかは、短い計算でわかります。

zn=Zn+δn,δn+1=2Znδn+δn2+δc

テキスト表記：z = Z + δ、このとき δ' = 2·Z·δ + δ² + δ_c

δ はごく小さいので、通常の浮動小数点数で十分な精度が得られます。GPU では、32 ビット浮動小数点数で表せるより小さな値に届くように、各 δ を仮数部と指数部に分けて保存します。折りたたみ型のフラクタルでは、|c+d|−|c| を求める補助関数を使い、桁落ちで桁が失われるのを防いでいます。

参照軌道が 1 本だけで、いつも代表になれるとは限りません。あるピクセル自身の軌道が、参照軌道よりも 0 に近づいたとき、差はもう小さくありません。そこでエクスプローラーは、そのピクセルをリベースします。差を完全な値 z に置き換え、参照軌道の先頭に対して計算をやり直すのです。これにより、素の摂動法で生じるグリッチが取り除かれます。どの参照点も有効なので、表示が離れすぎるまで現在の参照軌道を使い続けます。参照軌道はバックグラウンドのワーカーで計算されるので、ページが固まることはありません。

この方法により、べき乗が 2 のフラクタルは、約 10300 まで進めます。ほかのべき乗では直接の反復を使い、浮動小数点の精度の限界で止まります。限界に達したときは、エクスプローラーがお知らせします。

2 つのエンジンと正確な三角形

既定の GPU エンジンは、WebGL2 のシェーダーで何百万ものピクセルを並列に反復します。CPU エンジンは、64 ビットの数を使い、画像をワーカースレッドに分担させます。速度は落ちますが、WebGL がなくても動作します。シェルピンスキーの三角形は、脱出時間の反復も摂動法も使わず、そのページで説明したとおり、2 進数の桁を使った正確な計算だけで描かれます。
